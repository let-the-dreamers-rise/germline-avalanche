The mechanism

Reproduction is two transactions, and that is the point

Breeding in one step would let whoever runs it try seeds until one produced a configuration they liked. So it takes two, with a block boundary in between.

TX 1

requestSpawn(parentId)

Commits to breeding at a future block.

blockhash(requestBlock)             

The hash does not exist. Nothing about the child can be computed, predicted, or shopped for — not by the breeder, not by anyone.

TX 2

spawn(…)

Reveals the child, afterwards.

blockhash(requestBlock) 0x7c2f…a91e

Now the seed is fixed and the only remaining choices are to accept the child or abandon it — and abandoning it is recorded too.

seed = keccak256(parentGenomeRoot, blockhash(requestBlock), parentId, ordinal)

Anyone holding the parent re-runs the mutation offline and compares it against the child root on chain. A forged lineage fails arithmetic rather than failing to be believed.

Verification

Both outcomes are the feature working

A verifier that only ever says yes has told you nothing. These two tests run on every commit, and against a fork of Avalanche Fuji.

Accepted

An honest child

Bred through the real two-transaction path, re-derived from its parent and seed, and matched against what the chain recorded.

breeds one honest child that verify.js accepts as genuine

Refused

A forged child

Same parent, same seed, a configuration that seed could not have produced. The root disagrees, so it is rejected — no judgement call, no trust involved.

rejects a forged child whose genome root does not match its recorded seed

The benchmark we would rather you saw from us

Random sampling beats our own search, and we ship the control

An earlier version of this project claimed the search captured 80% of the available headroom for 21% of the budget. Both numbers were true and the claim was still wrong, because nobody had asked what random sampling does with the same budget.

The deciding column is sampled, not the size of the space. When you can afford a fifth of every possible configuration, drawing at random is close to optimal and no selection machinery earns its keep. Under one percent — which is what a real configuration space looks like, and the only row above built on recorded data — selection is ahead.

So Germline does not sell a better optimiser. It sells a verifiable record of whatever search you ran, and search() ships the random control switched on, reporting run.verdict.winner. If random wins on your space, use it and keep the lineage.

Why this chain

Two reasons specific to this mechanism

Finality is dead time here. The wait between commit and reveal exists for a security reason that cannot be optimised away — the seed must not exist when the breeder commits. That wait is time a user spends watching a spinner. Sub-second finality turns a security requirement into a non-issue; on a slow chain this mechanism is genuinely unpleasant to use.

A per-customer L1 is the regulated-deployment story. Provenance sells to teams whose own customers ask which version produced a given output — finance, health, anything audited. Those buyers frequently cannot put anything on a public chain. An Avalanche L1 lets a customer run the same registry, the same contract and the same verifier on a chain they control. That product shape does not exist on a monolithic chain.

Portability

The storage dependency was removed, not replaced

The chain carries a root; the bytes have to live somewhere. On 0G that was 0G Storage. The obvious way to leave is to depend on some other blob service instead — which trades one dependency for another and calls it portability.

But a root is keccak256 over canonical bytes, computed here, from bytes we hold. A reader can check what they were handed. So the store does not need to be trusted, decentralised, or even well behaved: it needs to return the bytes, and if it returns different ones the hash says so and the read is refused. A plain directory served over HTTP is a complete answer. 

GERMLINE_STORE=fs     # files on disk, no dependencies (default)
GERMLINE_STORE=http   # any static host; reads are verified
GERMLINE_STORE=0g     # 0G Storage, still available

The Avalanche claim, in one command

The heredity is seeded from blockhash. A chain that served historical block hashes differently would break commit-reveal silently — every child seeded from zero, every lineage verifying against a constant, and a green test suite the whole time. So it is checked against a real fork rather than asserted.
